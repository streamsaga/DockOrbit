# DockOrbit Deployment Guide

This guide details how to deploy **DockOrbit** to **Render** (using Blueprint or Web Services) as well as **Railway + Vercel**.

---

## Option 1: Deploy on Render (Recommended)

DockOrbit includes a pre-configured [`render.yaml`](file:///render.yaml) Blueprint file for one-click setup on Render.

### Method A: One-Click Render Blueprint (Backend Web Service + Frontend Static Site)

1. **Sign in to Render**: Log into [Render Dashboard](https://dashboard.render.com/).
2. **Create New Blueprint**:
   - Click **New +** > **Blueprint**.
   - Connect your GitHub repository (`DockOrbit` / `PROJ3`).
3. **Automatic Blueprint Detection**:
   - Render automatically reads [`render.yaml`](file:///render.yaml) from the repository root and provisions two services:
     - `dockorbit-backend` (Node.js Web Service)
     - `dockorbit-frontend` (Static Site with automatic SPA route rewrites)
4. **Configure Environment Variables**:
   Render will prompt you to enter values for required sync variables:
   - `DATABASE_URL`: Your PostgreSQL connection string (Supabase, Neon, or Render PostgreSQL).
   - `YOUTUBE_API_KEY`: Your YouTube Data API v3 key.
   - `OPENAI_API_KEY`: Your OpenAI API key (for channel trust score synthesis).
   - `GOOGLE_CLIENT_ID`: Your Google OAuth Client ID (optional, for Google Sign-In).
   - `VITE_GOOGLE_CLIENT_ID`: Match your `GOOGLE_CLIENT_ID` for frontend Google Sign-In button.
   - `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`: SMTP credentials for verification emails.
   - `USE_MOCK_DATA`: Set to `false` for live data or `true` to run without API keys.
   *Note: `JWT_SECRET` is auto-generated by Render, and `CORS_ORIGIN` is dynamically linked to your frontend URL.*
5. **Apply & Deploy**:
   - Click **Apply**. Render will build and launch both services automatically.

### Method B: Single Combined Web Service on Render (Monorepo)

If you prefer running both API endpoints and the React frontend inside a single Render Web Service:

1. **Create Web Service**:
   - Go to [Render Dashboard](https://dashboard.render.com/) > **New +** > **Web Service**.
   - Connect your GitHub repo.
2. **Configure Service Settings**:
   - **Name**: `dockorbit-app`
   - **Environment**: `Node`
   - **Branch**: `main`
   - **Root Directory**: *(leave blank to use repository root)*
   - **Build Command**: `npm install && cd frontend && npm install && npm run build`
   - **Start Command**: `npm start`
3. **Environment Variables**:
   Add the following in Render > **Environment**:
   - `PORT`: `10000`
   - `TRUST_PROXY`: `true`
   - `USE_MOCK_DATA`: `false`
   - `DATABASE_URL`: `postgresql://...`
   - `JWT_SECRET`: *(Set a strong secret key)*
   - `YOUTUBE_API_KEY`: `AIzaSy...`
   - `OPENAI_API_KEY`: `sk-proj...`
   - `GOOGLE_CLIENT_ID`: `your-google-client-id`
   - `SMTP_HOST`: `smtp.gmail.com`
   - `SMTP_PORT`: `587`
   - `SMTP_USER`: `your-email@gmail.com`
   - `SMTP_PASS`: `your-app-password`
   - `SMTP_FROM`: `your-email@gmail.com`
4. **Deploy**:
   - Click **Create Web Service**. Express automatically serves the built React app from `frontend/dist` for UI requests and `/api/*` for API requests.

## Option 2: Deploy on Railway + Vercel

### Step 1: Deploy Backend to Railway

1. **Create Railway Account**: Sign in to [Railway.app](https://railway.app/).
2. **New Project**:
   - Click **New Project** -> **Deploy from GitHub repo**.
   - Select your repository (`DockOrbit` / `PROJ3`).
3. **Configure Service Settings**:
   - Go to **Settings** > **General** > **Root Directory**.
   - Set **Root Directory** to `backend`.
4. **Set Environment Variables**:
   In your Railway Service > **Variables** tab, add key-value pairs (refer to [`backend/.env.example`](file:///backend/.env.example)):
   - `TRUST_PROXY`: `true`
   - `CORS_ORIGIN`: `https://your-app.vercel.app`
   - `DATABASE_URL`: `postgresql://postgres...`
   - `YOUTUBE_API_KEY`: `AIzaSy...`
   - `JWT_SECRET`: `your-secure-jwt-secret`
   - `OPENAI_API_KEY`: `sk-proj...`
   - `USE_MOCK_DATA`: `false`
5. **Generate Domain**:
   - Go to **Settings** > **Networking** > **Public Networking**.
   - Click **Generate Domain**.

---

### Step 2: Deploy Frontend to Vercel

1. **Create Vercel Account**: Sign in to [Vercel.com](https://vercel.com/).
2. **Import Project**:
   - Click **Add New** > **Project** > Import your repository.
3. **Configure Project Settings**:
   - **Framework Preset**: Vite
   - **Root Directory**: `frontend`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. **Set Environment Variables**:
   - `VITE_GOOGLE_CLIENT_ID`: `your-google-client-id`
5. **Configure API Rewrites in `frontend/vercel.json`**:
   Update `YOUR_RAILWAY_BACKEND_URL` in [`frontend/vercel.json`](file:///frontend/vercel.json).
6. **Deploy**: Click **Deploy**.

## Health Check & Verification

1. **Backend API Health Check**:
   Visit `https://<YOUR-BACKEND-URL>/api/categories`. It should return a JSON array of categories.
2. **Database Verification**:
   On first start, Express automatically runs database schema migration (`ensureTables()`) and creates required tables (`users`, `bookmarks`, `playlists`, etc.).
3. **Frontend SPA Check**:
   Open your deployed frontend URL. Test channel search, category browsing, bookmarking, and authentication.

## Troubleshooting

- **White Screen / `Failed to load module script: ... MIME type of "binary/octet-stream"` (`main.jsx:1`)**:
  - **Cause**: The web server is serving the raw un-compiled source `index.html` (which points to `/src/main.jsx`) instead of the production build output (`dist/index.html` which points to `/assets/index.js`).
  - **Fix for Render Static Site**: Ensure **Publish Directory** is set to `dist` (if Root Directory is `frontend`) or `frontend/dist` (if Root Directory is root), and **Build Command** is set to `npm install && npm run build`.
  - **Fix for Render Web Service (Monorepo)**: Ensure **Build Command** is set to `npm run build` so Vite compiles the React app into `frontend/dist` before starting `node src/server.js`.
  - **Fix for Local Dev**: Run `cd frontend && npm run dev` to start Vite dev server instead of serving raw files or opening `index.html` directly in the browser.
- **CORS Errors**: Ensure `CORS_ORIGIN` in backend environment matches your frontend URL (including `https://` without a trailing slash).
- **Rate Limit Warnings / IP match**: Ensure `TRUST_PROXY=true` is set so Express trusts proxy headers from Render or Railway.
- **404 on page refresh**: Ensure SPA rewrite rules (`/*` -> `/index.html`) are active in Render Blueprint or `vercel.json`.
